# 分享追踪与解析次数奖励

## 已实现规则

好友每次通过邀请链接重新进入，邀请人获得 5 次解析次数，不要求好友解析成功；同一好友可重复进入获得多次奖励。点击分享按钮本身不奖励，自邀不奖励。每次进入生成独立 entry_id，网络失败、身份未就绪、应用重启后的重试沿用原编号，后端只给该编号奖励一次。冷启动 App.onLaunch、App.onShow 和页面 onLoad 合并为同一次进入。

新增奖励与当日免费额度一起存入 daily_quotas.remaining，北京时间 00:00 开始新一天，旧日期余额和奖励不结转。每日默认额度仍由 DAILY_FREE_QUOTA 控制。奖励值由服务端 SHARE_REWARD 决定，默认 5；设为 0 则仅记录进入。

奖励由后端同一 MySQL 事务写入 share_invites、daily_quotas、quota_logs、share_visits。写入或提交失败时整体回滚；客户端保留原 entry_id 重试。前端不修改缓存余额，回到首页、点击次数提示或下拉刷新时通过 GET /api/v1/quota 获取当前剩余次数。

## 接口契约

当前默认使用 container / 微信云托管；电脑本机联调可显式切换 http / 127.0.0.1:8080。

| 接口 | 请求 | 说明 |
| --- | --- | --- |
| GET /api/share/profile | 无身份请求参数 | 获取本人服务器生成的邀请标识及 reward_per_friend、reward_rule |
| POST /api/share/log | `{ "inviter": "服务器返回的邀请标识", "source": "wechat_share", "entry_id": "32位小写十六进制进入编号" }` | 记录本次进入并原子发放奖励，返回 recorded、duplicate、reward_amount |
| GET /api/share/my-invitees | `before=0&limit=20` | 根据当前登录身份查询本人记录，返回 items、total、total_reward、next_cursor；limit 最大 50 |

与需求文档中的假设不同，当前项目没有 getApp().globalData.userId 登录模块；正式身份由微信私有网关注入，已有 trusted_identity 直接识别用户。前端不传 invitee/OpenID，不可通过 inviter_id 查询其他人的列表。分享路径中的 inviter 是随机邀请标识，不是原始 OpenID。后端会核对邀请所属小程序、用户状态，并拒绝自邀。记录页只展示本站好友编号及北京时间，不采集微信昵称、头像或手机号。

来源上报是通过分享参数进入时由客户端发起的业务事件；entry_id 防止同一事件重试重复加次，不是微信签名的“物理点击凭证”。按当前要求，不设置同一好友每天领取次数上限。

## 页面与缓存

- 实际首页保留桌面当前的 pages/home/index，分享卡片跳转该页面；pages/index/index 作为旧路径兼容跳转保留。
- App.onShow 捕获带分享参数的热启动；getEnterOptionsSync 仅用于参数缺失时兜底；页面 onLoad 捕获直接路径。
- 本地 guagua.pending.share.v1 只保存尚未上报的邀请标识、source 和 entry_id，最多保留 100 条；不保存或决定奖励余额。网络、401 或服务异常保留原编号；成功或永久无效链接移除对应事件。不能关闭 pending 缓存，否则应用重启后无法保证重试幂等。
- 首页有“我的邀请记录”，邀请列表支持 onShow 刷新、下拉刷新、加载更多和错误重试。累计奖励含历史日期，当前可用次数以首页接口为准。
- 分享资料未准备好时按钮禁用，右上角菜单使用默认分享路径，不伪造用户身份；配置成功后卡片包含 inviter/source 和自定义图。

## 数据库升级与发布顺序

1. **已导入旧五张表的数据库**：只执行 migrations/002_sharing.sql，新建 share_links、share_visits 两张表，不清空原表。
2. **全新空库**：依次执行 migrations/001_quotas.sql、002_sharing.sql，或使用本次更新包内完整初始化脚本。不要在已有同名表的库重复执行完整初始化。
3. 运行账号原权限之外需 share_links 的 SELECT/INSERT、share_visits 的 SELECT/INSERT/UPDATE、share_invites 的 SELECT/INSERT；已有 daily_quotas UPDATE、quota_logs INSERT 等权限继续保留。
4. 微信云托管中后端新增可选环境变量 SHARE_REWARD=5，部署本次后端。MySQL 仍使用云托管环境内的实例，后端走内网连接。
5. 确认 /api/share/profile、/api/share/log、/api/share/my-invitees 已部署后，前端 config/features.js 将 request.mode 改为 container，核对环境 ID 和服务名，重新编译上传。

本地模式仍固定 wxTestApp/openidA；同一电脑两个模拟器使用该模式也是同一个测试身份，打开自己的链接不会奖励。多身份奖励已通过独立 MySQL 集成测试验证；真实好友链路需云托管下两个不同微信账号验收。

## 验证

仓库根目录 `node tests/frontend.cjs` 验证前端本地/云模式、分享入口、重复打开生成新编号、失败重试保留编号、列表分页与下拉刷新。后端按 README 的 TEST_MYSQL_URL 流程运行 pytest；必须使用独立空测试库，不要指向现有业务或保留测试数据的库。
